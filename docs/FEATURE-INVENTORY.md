## Authentication compatibility

Inspected `backend/src/shared/routes/auth.routes.js`, `validators/auth.validator.js`, `utils/auth-cookies.js`, authorization and origin middleware (read-only).

**Phone + password authentication is BLOCKED.** No password login route, password credential validator or password verification flow exists. Only 10-digit phone + 6-digit OTP is supported. Requested password UI must never send passwords to the OTP endpoint or create a local role/session. Supported OTP can be offered separately without removing OTP checks. Cookies are HttpOnly; production uses Secure/SameSite=None. Existing backend CORS/origin configuration must already permit the local web origin for credentialed browser calls. This project must not change that configuration automatically.

## Browser verification requirements

- Browser equivalents needed for image picker/manipulation, alerts, file/PDF print/share and native navigation/lifecycle.
- Expo device push has no equivalent browser registration contract. Mark blocked; retain the existing inbox/polling where supported. Do not invent a push API.
- Shopping/customer-mode destinations stay outside this migration. Keep a clear native-app handoff and list lack of web customer destination as a boundary.
- Never run mutation acceptance tests against production. Use isolated fixtures with network interception; authenticated real-backend acceptance requires an explicitly configured local test backend and authorized test accounts.
- Native cleanup is NOT approved. Source coverage, successful compilation and mocked browser acceptance do not establish full real-backend parity.
