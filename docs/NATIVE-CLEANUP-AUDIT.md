## Current verification

- Full Playwright matrix: 168/172 passed. The four failures were two distinct mobile-only cases repeated on Android Chrome and iPhone WebKit emulation. The drawer did not restore focus to its opener after Escape, and an earnings test tried to use the desktop-only sidebar while mobile navigation was collapsed.
- Fixes: `web/src/features/seller/layout/seller-sidebar.tsx` now restores trigger focus when the mobile drawer closes with Escape or its close button. `web/tests/acceptance/seller.spec.ts` opens the mobile drawer before using its earnings link. `web/tests/acceptance/helpers.ts` and `seller-navigation.spec.ts` use the configured `localhost` origin consistently; host-only cookies do not cross between `localhost` and `127.0.0.1`.
- Focused rerun of all four previously failing Android/iPhone scenarios: 4/4 passed. Combined with the 168 passing full-matrix cases, every one of the 172 acceptance scenarios has a passing result, although the full matrix was not rerun after those final focused fixes.
- Web unit/contract suite: 17/17 passed. TypeScript, Prettier and `npm run audit:web` passed; audit reports 189 modules, 88 API call sites, zero React Native imports. The source integrity test confirmed original native files remained unchanged.

## Shared React Native files to preserve

- App/customer bootstrap and auth: `frontend/App.tsx`, `frontend/index.ts`, `frontend/navigation/RootNavigator.tsx`, `frontend/context/AuthContext.tsx`, `frontend/navigation/AuthNavigator.tsx`, `frontend/navigation/user/ShopNavigator.tsx`, and `frontend/services/auth/` / `frontend/services/api/`.
- Customer notifications and push: `frontend/features/notifications/NotificationProvider.tsx`, `NotificationsScreen.tsx`, and `frontend/hooks/usePushNotifications.ts` are mounted for the app/customer flow as well as role workspaces.
- Review/media components shared with customer orders/profile: `frontend/features/reviews/OrderReviews.tsx`, `ReviewForm.tsx`, `ReviewCard.tsx`, `frontend/services/media/image-upload.ts`, and `frontend/components/account/ProfileForm.tsx`.
- `frontend/components/ProfileDrawer.tsx` is shared customer UI and currently imports Seller registration and Admin store review entry points. It cannot be deleted as a role-only file.
- `frontend/components/shop/InventoryAlerts.tsx` imports `frontend/features/seller/seller.styles.ts`; that style module is not safe to remove without first replacing this customer dependency.
- `frontend/features/user/store-registration/StoreIcon.tsx` and `store-api.ts` are imported by Admin/Seller screens and the customer drawer/onboarding paths; preserve or refactor references before cleanup.

## Verdict

**Native cleanup: NO-GO.** Local workflow and emulated-browser parity are strong, but browser push is missing, physical-device/browser checks remain incomplete, and production integration was not verified. No native deletion list is authorized or prepared by this audit. Keep Admin/Seller native files until the missing capability is resolved or explicitly accepted, physical-device checks pass, production compatibility is verified, and the user separately approves cleanup.
